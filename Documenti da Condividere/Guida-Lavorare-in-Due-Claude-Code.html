Gestionale Creatio · lavoro a due mani

Lavorare in due sul gestionale con Claude Code

Come io (Giulio) e Kledi possiamo lavorare sullo stesso progetto, ognuno con il suo account Team, senza pestarci i piedi. La condivisione avviene tramite GitHub: è la "copia unica" del codice, ognuno la modifica dal suo PC e Git tiene tutto allineato.

💡 Da capire subito: Claude Code non è come Google Docs (niente stesso file live con due cursori). Ognuno lavora sui file sul proprio computer; ci si sincronizza mandando/ricevendo le modifiche con Git (push / pull).

Prerequisiti

  • Abbonamento Team: un posto (seat) per Giulio e uno per Kledi. Ognuno accede a Claude Code col proprio account.
  • Entrambi un account GitHub.
  • Claude Code installato su entrambi i PC.
  • Git installato (di solito arriva con Claude Code / o da git-scm.com).

1 · Setup una-tantum

Si fa una volta sola. La parte A la fa Giulio; la parte B la fa Kledi.

Fa Giulio
A) Mettere il progetto in un repository privato e invitare Kledi
  1. Ho già preparato un file .gitignore nella cartella del progetto: tiene fuori da Git i dati sensibili (CASSAFORTE, RISERVATO-password, .claude) e il repo di pubblicazione. Non toccarlo.
  2. Apri il progetto in Claude Code e digli: "crea un repository GitHub privato per questo progetto e fai il primo push". In alternativa, a mano nel terminale della cartella progetto: 
    # dentro la cartella del gestionale
git init
git add .
git commit -m "Progetto gestionale"
# crea il repo privato e carica (serve la GitHub CLI 'gh' loggata)
gh repo create gestionale --private --source=. --push
    ⚠️ Deve essere PRIVATO (contiene la logica del vostro gestionale).
  3. Su GitHub, apri il repo → Settings → Collaborators → Add people → inserisci l'username GitHub di Kledi.
📁 OneDrive: il progetto è dentro OneDrive. Git e OneDrive a volte litigano. Consiglio: come copia di lavoro futura, clona il repo in una cartella fuori da OneDrive (es. C:\Progetti\gestionale) e lavora da lì. (La cartella OneDrive attuale resta come backup.)
Fa Kledi
B) Scaricare il progetto e aprirlo
  1. Accetta l'invito al repository (arriva via email GitHub).
  2. Installa Claude Code e accedi con il tuo account (quello nel Team).
  3. Clona il progetto in una cartella tua (fuori da OneDrive): 
    git clone https://github.com/Giuliorm77/gestionale.git
cd gestionale
  4. Apri quella cartella in Claude Code. Da qui puoi lavorare esattamente come Giulio.

2 · Flusso di ogni giorno

Vale per entrambi, tutte le volte che ci mettete mano.

Fanno entrambi
  1. Prima di iniziare — scarica le ultime modifiche dell'altro: 
    git pull
  2. Lavora con Claude Code come al solito.
  3. Controlla che il file compili (evita di caricare errori): 
    node compilecheck.js
  4. Salva e condividi le tue modifiche: 
    git add -A
git commit -m "cosa ho cambiato"
git push
  5. Se git push viene rifiutato (l'altro ha caricato prima di te): fai git pull, risolvi eventuali conflitti, poi git push.
✅ Chiedere a Claude Code stesso "fai il commit e push delle modifiche" va benissimo: esegue lui questi comandi.

3 · La regola d'oro (per non pestarsi i piedi)

Il gestionale è un unico grande file (index.html). Se lo modificate nello stesso momento, al push nascono conflitti. Per evitarlo:

  • 🗣️ Coordinatevi: mettetevi d'accordo su chi ci lavora in un dato momento (un messaggio "ci sto lavorando io" basta).
  • ⏱️ Sessioni brevi: pull → fai una modifica → push subito. Meno tempo passa, meno conflitti.
  • 🔀 In alternativa (più avanzato): ognuno lavora su un proprio branch e poi si uniscono. Se vi serve, chiedete a Claude Code di impostarlo.
Se un conflitto capita, non è un dramma: Git segnala le righe in contrasto e Claude Code vi aiuta a risolverle. L'importante è non forzare (--force) i push.

4 · La pubblicazione (deploy) resta invariata

Il sito online (gestionale.creatiogroup.it) si aggiorna come adesso: si copia index.html nella cartella di pubblicazione e si fa push del suo repository (Cloudflare pubblica da lì). Chi sviluppa e chi pubblica possono essere la stessa persona o no: decidete chi "manda in produzione" per evitare di pubblicare cose a metà. Anche qui potete chiedere a Claude Code di farlo.

🔴 Regola importante: si pubblica solo dopo il node compilecheck.js OK. E dopo un aggiornamento, ai colleghi va detto Ctrl+Shift+R per vedere la versione nuova.

5 · Cosa NON fare

  • ❌ Non condividere il progetto copiando la cartella su OneDrive/USB: si sovrascrivereste a vicenda e si perde lo storico. Si usa solo Git.
  • ❌ Non mettere il repository pubblico: deve restare privato.
  • ❌ Non caricare su Git i file segreti (chiavi, password): ci pensa il .gitignore, non rimuoverlo.
  • ❌ Non usare git push --force: cancella il lavoro dell'altro.
